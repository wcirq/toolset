# 会话后端实施状态

## UIA

设置 → 微信助手 → 会话接入方式。吸附微信后，右键 → 微信聊天助手 → 绑定会话 / 轮流切换 / 填写回复。

读取当前实现的 session_list，通过 session_item_ 前缀提取名称；绑定同时保存 RuntimeId，拒绝同名或重建的列表项。勾选多个会话后手动轮流切换，生成回复，再填写输入框，不自动发送。仅使用 UIA，无截图、OCR、剪贴板回退。

切换要求当前输入框无草稿；读取及填写要求列表选中状态、输入框标题和 RuntimeId 一致。填写前还检查消息文本未改变。客户端必须支持 SelectionItem.Select 和 Value.SetValue；目前未在真实客户端完成这两项端到端验证。不支持这些 Pattern 时明确报错。

宠物可拖到可见聊天行，出现“聊天：名称”预览后松开吸附。后台每约 250 毫秒读取行坐标，跟随行排序和窗口移动；行不可见或绑定失效时隐藏，原 RuntimeId 再次出现后恢复。客户端重建列表项时需重新拖动绑定，不按同名自动换绑。这一交互已通过单元测试，尚未完成真实客户端验证。

尚未实现定时轮询消息、后台持续监听和自动发送。消息方向、发送人和稳定消息 ID 尚未得到可靠识别，因此不能直接把文本变化当作收到新消息。

## 进程内

当前为明确不可用状态，选择后操作报错，不会回退到 UIA。

只有安装包，无源码、PDB 或接口说明。对安装目录 4.1.13.12 的五个 PE 文件执行静态导入导出及 SHA-256 检查，详见 weixin-4.1.13.12-pe.json；复现工具为 tools/inspect_weixin_binary.py。

Weixin.dll 导出 SetWeixinCallbackFunc（RVA 0x305c80），但名称不足以证明这是聊天回调。ilink2.dll 导出包含 AppSession/CloudSession/DeviceSession 的 C++ 符号，尚未确认个人/群消息协议或收发 ABI。未调用任何猜测地址，也未将现有 SendGuard 键鼠 Hook 宣称为消息收发 Hook。

要完成此后端，仍需在隔离测试账号环境确认接收入口、会话业务 ID、消息结构与生命周期、发送函数调用约定和线程要求，并按二进制指纹锁定版本。当前静态报告不具备这些信息。
